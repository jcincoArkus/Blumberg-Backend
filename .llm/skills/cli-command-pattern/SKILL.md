# CLI Command Pattern

CLI lives at `Apps/CLI/`. Uses `System.CommandLine` (beta4). Commands are static methods that return `Command`.

## File Structure

```
Apps/CLI/
├── Program.cs                    # Entry point — register commands here
├── Commands/
│   └── {Domain}Commands.cs       # Command group (static class)
└── Generators/                   # Optional — code-gen helpers
    └── {Name}Generator.cs
```

## Simple Command (ILoggerFactory only)

For commands that only need DB access via `ApplicationDbContextFactory.Create()`:

```csharp
using System.CommandLine;
using Adapters.Database;
using Microsoft.Extensions.Logging;

namespace CLI.Commands;

/// <summary>
/// Item management commands
/// </summary>
public static class ItemCommands
{
    public static Command SyncItems(ILoggerFactory loggerFactory)
    {
        var logger = loggerFactory.CreateLogger("ItemSync");
        var command = new Command("item:sync", "Sync items from external source");

        // Arguments (positional, required)
        var sourceArg = new Argument<string>("source", "Source system name");
        command.AddArgument(sourceArg);

        // Options (named, optional)
        var dryRunOption = new Option<bool>(
            name: "--dry-run",
            description: "Preview changes without applying",
            getDefaultValue: () => false);
        command.AddOption(dryRunOption);

        command.SetHandler(async (string source, bool dryRun) =>
        {
            try
            {
                logger.LogInformation("Syncing items from {Source} (dry run: {DryRun})", source, dryRun);

                await using var context = ApplicationDbContextFactory.Create();
                // ... command logic

                logger.LogInformation("Item sync completed");
            }
            catch (Exception ex)
            {
                logger.LogError(ex, "Failed to sync items");
                Environment.Exit(1);
            }
        }, sourceArg, dryRunOption);

        return command;
    }
}
```

## Command with Full DI (IServiceProvider)

For commands needing registered services beyond just the DB context:

```csharp
public static Command ImportData(IServiceProvider serviceProvider, ILoggerFactory loggerFactory)
{
    var logger = loggerFactory.CreateLogger("DataImport");
    var command = new Command("data:import", "Import data from CSV file");

    var fileArg = new Argument<string>("file", "Path to CSV file");
    command.AddArgument(fileArg);

    command.SetHandler(async (string file) =>
    {
        try
        {
            logger.LogInformation("Importing data from {File}", file);
            var myService = serviceProvider.GetRequiredService<IMyService>();
            // ... command logic
            logger.LogInformation("Data import completed");
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "Failed to import data");
            Environment.Exit(1);
        }
    }, fileArg);

    return command;
}
```

## No-arg Command

```csharp
public static Command ResetCache(ILoggerFactory loggerFactory)
{
    var logger = loggerFactory.CreateLogger("CacheReset");
    var command = new Command("cache:reset", "Clear all cached data");

    command.SetHandler(async () =>
    {
        try
        {
            logger.LogInformation("Resetting cache");
            // ... command logic
            logger.LogInformation("Cache reset completed");
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "Failed to reset cache");
            Environment.Exit(1);
        }
    });

    return command;
}
```

## Code Generator (optional)

For commands that generate C# source files, extract logic into `Apps/CLI/Generators/`:

```csharp
using System.Text;
using Microsoft.Extensions.Logging;

namespace CLI.Generators;

public class ItemCodeGenerator(ILogger logger)
{
    private const string OutputPath = "Shared/Generated/Items.cs";

    public async Task GenerateAsync()
    {
        logger.LogInformation("Generating item code");

        var sb = new StringBuilder();
        sb.AppendLine("// Code generated by CLI item:generate; DO NOT EDIT manually.");
        sb.AppendLine($"// Generated at {DateTime.UtcNow:yyyy-MM-dd HH:mm:ss} UTC");
        // ... build code

        await File.WriteAllTextAsync(OutputPath, sb.ToString());
        logger.LogInformation("Generated {Path}", OutputPath);
    }
}
```

Use from command:

```csharp
command.SetHandler(async () =>
{
    var generator = new ItemCodeGenerator(logger);
    await generator.GenerateAsync();
});
```

## Registration in Program.cs

Add commands to the root command in `Apps/CLI/Program.cs`:

```csharp
// Simple commands (ILoggerFactory only)
rootCommand.AddCommand(ItemCommands.SyncItems(loggerFactory));

// Commands needing DI (IServiceProvider)
rootCommand.AddCommand(ItemCommands.ImportData(serviceProvider, loggerFactory));
```

If the command needs new services in the DI container, register them in the `services` block at the top of Program.cs:

```csharp
var services = new ServiceCollection();
services.AddLogging(builder => builder.AddSerilog(logger));
services.AddDbContext<ApplicationDbContext>(options =>
    options.UseNpgsql(config.Database.GetConnectionString()));
services.AddScoped<IMyService, MyService>();  // <-- add here
var serviceProvider = services.BuildServiceProvider();
```

## Project Conventions

- **File location**: `Apps/CLI/Commands/{Domain}Commands.cs` — static class, one per domain
- **Naming**: Colon-separated `domain:action` (e.g., `migration:generate`, `permission:init`)
- **Method signature**: `public static Command MethodName(ILoggerFactory loggerFactory)` or add `IServiceProvider` as first param when needed
- **Error handling**: try-catch with `Environment.Exit(1)` on failure — never let exceptions bubble
- **Logging**: `ILoggerFactory.CreateLogger("CommandName")` — Info on start/success, Error on failure
- **DB access**: Use `ApplicationDbContextFactory.Create()` for simple DB commands (no DI needed)
- **Full DI**: Pass `IServiceProvider` when needing registered services beyond the DB context
- **Async**: All handlers should be async (`command.SetHandler(async () => { ... })`)
- **Generators**: Extract code-gen logic into `Apps/CLI/Generators/` — keep commands thin
- **Registration**: Add `rootCommand.AddCommand(...)` in `Program.cs` with a comment grouping

## Checklist

1. Create `Apps/CLI/Commands/{Domain}Commands.cs` (static class)
2. Add static method returning `Command` with arguments/options
3. Implement handler with try-catch + `Environment.Exit(1)`
4. Register in `Program.cs` via `rootCommand.AddCommand(...)`
5. If using DI services, register them in the `ServiceCollection` block in Program.cs
